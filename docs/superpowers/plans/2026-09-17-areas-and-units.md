# Areas, Sub-Areas & Units Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Super Admin can manage Areas and Sub-Areas; Area Admins (scoped to their assigned areas) and Super Admin can create and browse permanent Property Units and their Unit Spaces (floors).

**Architecture:** Server Components read directly from Supabase (RLS-gated); Server Actions handle all writes, each re-checking the actor's role via `getCurrentProfile()` before touching the database (RLS is the real boundary, this is the UX-level gate that avoids a wasted round trip for someone who clearly can't do the action). Units are permanent — no delete/edit-in-place workflow in this plan beyond creation and adding spaces; broader edit/archive lands in a later plan.

**Tech Stack:** Next.js Server Components/Actions, Supabase (`@supabase/ssr` server client already in `src/lib/supabase/server.ts`), Tailwind (existing conventions from `src/app/(app)/admin/users/page.tsx`).

## Schema This Plan Assumes (already deployed — do not re-create)

From `supabase/migrations/0001_phase1_schema.sql`, `0003_grant_authenticated_privileges.sql`, and `0004_area_codes_and_unit_code_generation.sql`:

- `areas(id uuid, name text, code text unique not null, status text)`
- `sub_areas(id uuid, area_id uuid, name text, code text not null, population text, consumer_type text, commercial_profile text, remarks text)` — `(area_id, code)` unique
- `area_admins(profile_id uuid, area_id uuid)` — junction table for multi-area assignment
- `units(id uuid, unit_code text unique not null [auto-generated by trigger — never insert this column], sub_area_id uuid not null, jalan text, unit_no text, full_address text not null, lat double precision, lng double precision, facing text, property_type text, land_type text, tenure text, tenure_years integer, cf boolean, iwk boolean, hakmilik text, unit_size numeric, unit_size_type text, location_url text, banner_status text, remarks text, status text default 'active', created_by uuid, created_at, updated_by uuid, updated_at)`
- `unit_spaces(id uuid, unit_id uuid, floor_type text not null, floor_label text not null, size numeric, size_type text, separate_owner boolean default false, status text default 'active', remarks text, created_at)`

RLS already deployed (from `0001_phase1_schema.sql`):
- `areas`/`sub_areas`: SELECT for any authenticated user; INSERT/UPDATE/DELETE only `super_admin`.
- `units`/`unit_spaces`: SELECT for any authenticated user (no owner PII in these tables); INSERT/UPDATE restricted to `super_admin` or an `area_admin` assigned to that unit's area (via `is_area_admin_for_area(area_id_for_sub_area(sub_area_id))` / `area_id_for_unit(unit_id)`).

Because RLS already scopes writes correctly, this plan's Server Actions do a role check for UX (redirect people who obviously can't do the action before they fill out a form) but the database is the actual enforcement — a bug in the UI-level check cannot grant unauthorized access.

## Global Constraints

- Light theme, white background, sky-blue accents, mobile-first (spec §39) — reuse the exact Tailwind classes already used in `src/app/(app)/admin/users/page.tsx` (`border-sky-100`, `bg-sky-600`, `text-slate-900`, `border-slate-300`, etc.) for visual consistency.
- Units are permanent — never deleted, only archived via `status` (spec §4). This plan does not build an archive UI; just don't build a delete button.
- `unit_code` must never be supplied by the app — omit it entirely from insert payloads so the `trg_generate_unit_code` trigger fills it (spec §40: no manual key-in).
- Area Admin write access is scoped to their assigned area(s) only (spec §3) — already enforced by RLS; this plan's create-unit form must only offer sub-areas within the actor's assigned areas when the actor is an `area_admin` (Super Admin sees all).
- Population/Consumer Type live on `sub_areas` only, never duplicated per-unit (spec §3).

import { createClient } from "@/lib/supabase/server";
import type { Role } from "@/lib/auth/role";

export function canSeeAllAreas(role: Role): boolean {
  return role === "super_admin";
}

// Returns the area ids this user is an Area Admin for. Meaningless for
// super_admin (who can see/write everywhere regardless) — callers should
// check canSeeAllAreas(role) first and skip calling this for super_admin.
export async function getAdminAreaIds(profileId: string): Promise<string[]> {
  const supabase = await createClient();
  const { data } = await supabase
    .from("area_admins")
    .select("area_id")
    .eq("profile_id", profileId);

  return (data ?? []).map((row) => row.area_id);
}

export async function createArea(formData: FormData) {
  const actor = await getCurrentProfile();
  if (!actor || actor.role !== "super_admin") {
    redirect("/");

  const name = String(formData.get("name"));
  const code = String(formData.get("code")).toUpperCase();

  }

  redirect("/admin/areas?created=1");
}

export async function createUnitSpace(formData: FormData) {

    redirect("/");
  }

  const unitId = String(formData.get("unitId"));

  });
